# 简历回填模板 v1（项目二版）

> 用途：把 ContentOps Agent 写进简历第 2 段项目经历。
> 规则：**没在仓库里查到的数字，一个都不许写。** 面试官问一句「这数怎么来的」，编的当场就破。
> 上一版的「30 条黄金集 / 命中率 100%」已随流程退役，**从简历里删干净**。

---

## 一、现在能写（全部可在仓库里查证）

- 用 LangGraph 1.x 的 `StateGraph` 搭 **7 节点**流水线：选题 → 人工选 → 写稿 → 人工审 → 提炼图点 → 并行出图 → 双平台发布。
- 用 `interrupt()` 实现 **两次真人中断**：图真的挂起、状态写进 checkpointer、进程可以退出；
  换一个进程用同一个 `thread_id` 就能接着跑。打回带意见回到写稿节点重写，上限 3 版，到顶收工不硬发。
- **三种状态后端**可切换：内存 / SQLite / PostgreSQL（`--pg`，四张表自动建，autocommit 建表避开
  `CREATE INDEX CONCURRENTLY` 的事务限制）。
- 节点拆成三张独立编译的**子图**（选题 / 写作 / 配图），人机交接全部留在主图，恢复点语义稳定。
- **结构化输出**用 JSON Mode + Pydantic 校验，校验失败退回文本解析；节点级 token / 耗时写进 state，
  页面直接出**成本表**（不用 LangSmith）。
- **出图**：同步 API 丢线程池并行（5 张 32 秒），指数退避重试（1s→2s→4s），单张失败只进 `image_errors`、不阻断发稿。
- **自建 trace**：`runs` + `events` 两张 sqlite 表，配 Vue3 页面（零构建，Vue 已 vendor）；支持 `/app/#run=<id>` 直达。
- **自建评测**：12 条真实方向 + 四项可机判指标（选题 / 成稿 / 图点 / 出图），一条命令出报告 + 失败明细 + 口径；
  口径调整保留前后两份报告做对照。
- **77 条测试 + CI**：含一条**真起三个子进程**的用例（A 停 → B 选 → C 放行），验证跨进程恢复不是模拟的。
- 无 key 自动回落 mock，`clone` 下来三条命令就能跑；有 key 直接切真模型。

## 三、成稿（挑 3-4 条放简历，别全塞）

> **ContentOps Agent —— 自媒体运营多智能体流水线**（个人项目，2026.11–）
>
> ▪ 基于 LangGraph 1.x 搭建 7 节点内容流水线（选题→人工选→写稿→人工审→图点→并行出图→双平台发布），
> 用 `interrupt()` 实现两次真人中断：图挂起、状态落 checkpointer、进程可退出，换进程凭同一 `thread_id` 续跑；
> 打回带意见重写，上限 3 版。
> ▪ 设计三种可切换的状态后端（内存 / SQLite / PostgreSQL），并用真起三个子进程的用例验证「A 停 → B 选 → C 放行」；
> PostgreSQL 侧用 autocommit 连接建表，避开 `CREATE INDEX CONCURRENTLY` 的事务限制。
> ▪ 结构化输出采用 JSON Mode + Pydantic 校验并保留文本解析兜底；节点级 token 与耗时写入状态，
> 页面呈现成本表与 trace 时间线（自建 `runs`/`events` 两张表，不依赖 LangSmith）。
> ▪ 出图链路把同步 API 丢线程池并行（5 张 32 秒）、指数退避重试、失败降级为 `image_errors`；
> 真模型实测单篇成本约 ¥1，77 条测试全绿、CI 通过。
> ▪ 自建评测：12 条真实选题方向、四项可机判指标（选题 / 成稿 / 图点 / 出图），
> 实跑 **11 条通过**（选题 96.7% / 成稿 100% / 图点 97.9%），12 条共 ¥0.0284；
> 口径调整保留前后两份报告，失败样本逐条留原因、不为好看调阈值。
> ▪ 已知边界：事实核查随流程切换退役，当前防线是人工审核那一次中断；发布为稿件生成，未对接平台 API。

> 最后那条「已知边界」建议**保留**。面试官看到主动写局限，反而会相信前面那些数。

## 四、和第一段的分工

| 简历段落 | 证明什么 | 一句话 |
|---|---|---|
| 智能笔记助手（已有） | 能改造别人的开源项目、把链路跑通并压指标 | 复现 + 二次改造 |

因为它有真实的取舍（评测砍过又补回）、真实的坑（子图重放、`checkpoint_id`）。

## 五、面试边界（哪些不能吹）

| 不能吹 | 会被怎么问穿 | 该怎么说 |
|---|---|---|
| "准确率 / 命中率 xx%" | "哪份报告？我能看看吗" | 评测是形状口径（长度/段落/同质化），不是内容准确率 |
| "自研 Agent 框架" | "你那套调度器怎么写的" | 用 LangGraph 编排，工程取舍见 ADR |
| "对接了小红书/公众号" | "审核怎么过的" | 生成两个平台稿件，落本地，未接平台 API |
| "上线了公网 demo" | "发我链接" | 本地可跑 + 录屏，未部署 |
| "高并发、可扩展" | "压测数据呢" | 只说具体做了三种后端和 SSE，限流没做 |

## 六、别做的事

- 不要写"精通 LangGraph"。写清楚做过哪些节点、为什么这么切、什么情况下会退化。
- 不要把"跟着课程做的"写成"自研"。被追问课程名答不出来，信任成本极高。
- 不要罗列七个框架名充数。一个项目讲透，胜过七个都停在 import。
- 不要把测试数写成"覆盖率达 xx%"，没跑过覆盖率就别提覆盖率。
