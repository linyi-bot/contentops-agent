# 简历回填模板（阶段 3 出数之后才动这里）

> 用途：把 ContentOps Agent 写进 `林毅_AI Agent实习简历_新版式.docx` 的第 2 段项目经历。
> 规则：**方括号里的数字没测出来之前，一个都不许编。** 面试官只要问一句「这个 90% 是怎么算的」，
> 编的数字就当场破。

## 一、现在能写（已有事实，不需要额外数据）

- 用 LangGraph 1.x 的 `StateGraph` 搭 选题 → 检索 → 起草 → 事实核查 → 人工审核 → 发布 六节点流水线，节点纯函数化，可单测。
- 两条条件边构成回写环：核查不过自动重写、人工打回也重写，共享 `MAX_REVISION=3` 额度，额度用尽就交人而不是硬发。
- 人工中断用 `interrupt()` + checkpointer 实现：图真的挂起、可恢复；阶段 3 换成 SQLite checkpointer 后，
  `--db` 落盘，进程退出再换一个进程 `resume` 也能接着发布（打回则在新进程里重写一版再停）；审核包自带每条断言的核查结论。
- 事实核查只做可机判的两件事 —— 引用编号必须在检索范围内、引用段落与断言至少共享 2 个实字或 1 个数字/单词（专抓「引错段」）；语义是否支持明确交给人，不假装能判。
- 空稿 / 零命中不算「通过」：发布记录里标 `forced`，逼人工确认，防止模型返回空内容时一路绿灯。
- 自建 trace：每节点记录耗时与一句人话说明，不依赖 LangSmith 付费服务即可定位问题节点。
- 知识库与流水线解耦：语料是纯 markdown，按二级标题分块，换场景只换 `docs/kb/`。
- 无 API key 时自动回落 mock 模型（且 mock 会真读检索编号标引用）—— 保证「clone 下来就能跑」，`pytest` 23 条用例全绿；CI 工作流已配好（push 后生效）。
- 建了 30 条黄金集（10 常规 / 10 边界 / 10 应拒答）与评测器：一条命令出汇总表 + 失败明细，
  每改一次闸门/提示词就留一份报告对照。第一轮跑完发现 3 个问题（mock 丢首条资料、
  单字切分区分度不足、没有相关度闸门），端到端通过率 4/30 → 30/30，拒答准确率 10% → 100%。

> 这段可以写，因为它是**过程和事实**，不是模型效果。写的时候带上「mock 基线」三个字；
> 面试被问「准确率多少」时，答「这组数测的是流水线行为，不是模型质量，换成真模型要重跑」——
> 这句话本身就是加分项，别把它藏起来。

## 三、成稿的样子

> **ContentOps Agent —— 内容运营多智能体工作台**（个人项目，2026.11–）
>
> ▪ 为内容团队做「选题 → 检索 → 起草 → 事实核查 → 人工审核 → 发布」六节点流水线，用 LangGraph 编排，
> 人工中断只放在对外发布前与涉及承诺的表述处，其它环节全自动。
> ▪ 建 30 条黄金集（10 常规 / 10 边界 / 10 应拒答）与评测器：一条命令出汇总表 + 失败明细，
> 第一轮跑出 3 个问题，端到端通过率 4/30 → 30/30，拒答准确率 10% → 100%（mock 基线，33 ms / P95 40 ms）。
> ▪ 自建 trace 与失败明细报告，能定位是召回不准还是提示词没写清；相关度闸门 0.09 挡住不相关选题。
> ▪ 代价：知识库无命中时明确拒答而不硬编；超短查询会被闸门误拒；覆盖不到的长尾选题需人工补料。

> 上面这段现在就能用（数字都来自 `reports/`）。等真模型跑完，把「mock 基线」四个字和延迟数字换掉，
> 再补 token 成本那一项 —— 其余句子不用动。

## 四、和现稿第 1 段的分工

| 简历段落 | 证明什么 | 一句话 |
|---|---|---|
| 智能笔记助手（已有） | 能改造别人的开源项目，把链路跑通并压指标 | 复现 + 二次改造 |
| ContentOps Agent（待补） | 能从 0 设计多智能体协作、做评测与部署 | 从 0 到 1 |

两段不重复：一段证明「改得动」，一段证明「建得起」。面试被问「你最能讲的项目是哪个」，
答案应该是后者，因为它有评测和实施代价。

## 五、别做的事

- 不要写「精通 LangGraph」。写清楚做过什么节点、为什么这么切、什么情况下会退化。
- 不要把「跟着课程做的」写成「自研」。被追问课程名时答不出来，信任成本极高。
- 不要罗列 7 个框架名充数。一个项目讲透，胜过七个都只停在 import。
