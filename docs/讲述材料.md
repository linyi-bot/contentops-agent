# 讲述材料 v1（3 分钟讲稿 + 录屏分镜 + 十个必问题）

> 面向：AI Agent / 应用开发岗面试，以及录屏演示。
> 口径：**真模型 `deepseek-flash` + 火山 Seedream 5.0-flash**，单条运行；数字出处见文末第五节。
> 纪律：只讲仓库里查得到的数。旧版那套「30 条黄金集、命中率 100%」随流程退役了，**不许再用**。

## 一、3 分钟口播稿（约 800 字，语速 260 字/分钟）

### [0:00–0:25] 一句话说清它是什么

> 我做的是一个**自媒体运营的多智能体流水线**。你给一个方向，它出五个选题；你挑一个，它写稿；
> 稿子写完停下来让你审，你放行它才去出图，出完图自动生成小红书和公众号两个版本。
>
> 关键词不是"AI 写文章"——那个谁都能调 API。这个项目解决的是**人机怎么交接**：
> 哪些活机器干、哪些必须停下来等人、人走了之后流程怎么接得上。

### [0:25–0:55] 它到底解决什么痛点

> 内容团队真正累的不是写不出来，是**每一步都要人盯着**：选题要人想、初稿要人改、
> 改完不知道是第几版、配图要人拆图点再一张张生成。
>
> 更麻烦的是**人一离开，流程就断在那儿**：稿子停在"等主编看一眼"，主编出差三天，这三天它就死着。
>
> 所以这个项目把一条链路做成了状态机：机器能干的自动干，必须人决定的停下来等，**停多久都行**。

### [0:55–1:45] 怎么做的（这是重点，要慢）

> 整条链路用 LangGraph 的 `StateGraph` 编排，七个节点：
> `plan_topics` 出选题、`human_select` 人选、`write_draft` 写稿、`human_review` 人审、
> `extract_visuals` 提炼图点、`generate_images` 并行出图、`publish` 双平台发布。
>
> 中间**两次 `interrupt()`**。它不是"弹个框问你"，是**把整个图挂起、状态写进 checkpointer、
> 进程可以退出**。第二天你换个进程，用同一个 `thread_id` 就能接着跑。
>
> 打回的时候带着意见回到写稿节点重写，最多三版；三版还不行就收工，**不硬发**。
>
> 三个节点是独立的子图（选题 / 写作 / 配图），主图负责编排，人机交接全部留在主图——
> 这样恢复点永远是"主图走到第几个节点"，语义稳定。

### [1:45–2:25] 工程上真正难的三件事

> **第一，中断恢复时节点会重跑。** LangGraph 的语义是"节点要么整体提交、要么整体不提交"，
> 所以恢复时那个节点会重新执行一遍。节点里除了构造审核包，不能有任何副作用。
>
> **第二，子图不能直接挂成节点。** 我一开始直接 `add_node(子图)`，结果每次 `resume` 主图
> 把子图连同上游重放一遍，`operator.add` 的 trace 从 7 条变成 15 条。后来包了一层、
> 只回传增量才对。
>
> **第三，时间旅行不是改个参数。** `update_state()` 没有 `checkpoint_id` 参数——网上不少示例
> 还在那么写，直接 `TypeError`。正确做法是把 `checkpoint_id` 和 `checkpoint_ns` 放进 `config`，
> 再 `invoke(None, cfg)`。

### [2:25–2:50] 数据

> 一条真跑的记录：选题 1.4 秒、写稿 3.2 秒（流式，页面能看到字一个个出来）、
> 提炼图点 1.1 秒、出五张图 31.7 秒，发布零耗时。文本不到一分钱，图五张约一块钱。
>
> 还有一份评测：12 条真实方向跑下来 **11 条通过**，选题合格率 96.7%、成稿 100%、图点 97.9%，
> 12 条一共花了 3 分钱。仓库 77 条测试全绿，CI 每次 push 跑一遍，
> 里面有一条是**真起三个子进程**验证跨进程恢复。

### [2:50–3:00] 收尾（要主动交底）

> 一句话总结：**能自动的自动，不能自动的停下来等人，停多久都不丢。**
>
> 边界我也说清楚：这版**没有做事实核查**，模型编了看不出来；
> 发布是生成稿件、不是真对接平台；这些都在 README 的"已知限制"里写着。

3. 结尾主动说边界（没做事实核查、发布是生成本地稿）——**主动交底比被问出来强**。

## 三、十个必问题（面试前背这十条）

### Q1. 为什么用 LangGraph，不自己写个状态机？
> 因为它把三件难事做完了：中断点、恢复、历史回放。自己写等于重造一个不完整的 checkpoint 机制。
> 代价是多一层抽象，而且社区教程大量停留在 0.x 的 `interrupt_before`，容易照抄错。

**追问陷阱**："那你是不是只会调框架？" → 答：讲 `update_state` 的坑、子图重放、恢复重跑这三条。

### Q2. 中断恢复时节点会重跑，你怎么保证不出错？
> 节点里只构造 packet，不做副作用；写稿节点即使重跑也只是重新生成一版，revision 用 state 里的值 +1。
> 真正要小心的是"发消息、扣钱"这类操作，那种必须用幂等键。

### Q3. 子图为什么又包了一层函数？
> 直接 `add_node(CompiledStateGraph)` 时，resume 会把子图连同上游重放，trace 从 7 条涨到 15 条。
> 包一层只回传增量，行为就和普通节点一致；子图仍然独立编译、可单测。

### Q4. 结构化输出为什么不用 `with_structured_output`？
> 它返回的是解析后的 Pydantic 对象，拿不到 `usage`，我就没法记每个节点烧了多少 token。
> 所以用 JSON Mode + 手动 `model_validate`，顺带能拿到原始响应用于报错。

### Q5. 时间旅行怎么做的？
> `history()` 列出所有 checkpoint；`rewind()` 把 `checkpoint_id` + `checkpoint_ns` 放进 config，
> `update_state` 开一条新分支，再 `invoke(None, cfg)` 往下跑。

### Q6. 出图为什么 32 秒？能优化吗？
> 五张图是**并行**发的（线程池），单张约 6-8 秒，所以总时长接近单张而不是五倍。
> 再快只能换更小的模型或降分辨率，但会掉质量。

### Q7. 成本怎么算的？
> 文本按官方定价乘 token（这次 906 token，不到一分钱）；图按张算，flash 约 0.2 元一张，
> 五张一块钱。所以一篇成品 ≈ ¥1，其中 99% 是图的钱。

### Q8. （最容易被问）模型胡编怎么办？你这版没有事实核查吧？
> **承认**：没有。上一版有事实核查节点（引用编号校验 + 段落关键词重合），换成自媒体流程后退役了。
> 现在的防线是"人工审核那一次中断"——稿子必须人看过才能出图。
> 下一步把核查按新流程重做，做成"图点必须来自正文"这种可机判的规则。

### Q9. 这和课程项目有什么区别？
> 流程骨架来自课程（选题→人选→写稿→人审→出图），我自己加了三样课程没有的：
> 自建 trace + 节点成本（课程用 LangSmith，要付费要外网）、三种 checkpointer（课程只有 PG）、
> 零构建的 Vue 部署方式（受限机器上 `npm install` 随时会挂）。
> 评测也重做了一版：课程那套跟的是旧流程，换成这里后指标全不对，我按新流程重定了四项。

### Q10. 这个项目你最大的取舍是什么？
> **砍过一版评测，后来又补回来了。** 上一版有 30 条黄金集和四个指标，换成自媒体流程后指标对不上了，
> 我选择整个退役而不是留一份解释不清的报告；这一版按新流程重定了四项可机判指标
> （选题 / 成稿 / 图点 / 出图），12 条方向跑下来 11 条通过。
> 代价是这四项只测「形状」不测「内容质量」，报告里明写了这一点，不包装成准确率。

### Q11（追加）. 你的评测怎么证明不是自说自话？
> 三个办法：**阈值写在代码里**（`eval.py` 的 `score_topics/score_draft/score_points`，可单测）；
> **失败明细逐条留着**（这次留了一条真实的同质化失败，没为了好看去调阈值）；
> **口径写在报告里**（哪四项、分子分母是什么、不测什么）。
