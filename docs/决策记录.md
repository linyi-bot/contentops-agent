# 决策记录（ADR）

> 只记「当时为什么这么选、代价是什么」。功能和用法看 README。
> 每条都能在面试里直接讲成「我遇到过什么问题、比较了哪几个方案、最后为什么选这个」。

---

## ADR-01 编排用 LangGraph，而不是自己写状态机

**背景**：流程里有两次人工中断，且要求进程退出后还能接着跑。

**选项**
1. 自己写一个 `while` 状态机 + 把状态存数据库；
2. LangGraph（`StateGraph` + `interrupt()` + checkpointer）。

**选择**：2。

**理由**：中断点、恢复、历史回放这三件事 LangGraph 已经实现且被大量项目验证；自己写等于重造一个不完整的 checkpoint 机制。

**代价**：多一层抽象，`resume` 时节点会重跑（必须写幂等节点）；社区教程大量停留在 0.x 的 `interrupt_before`，容易照抄错。

---

## ADR-02 中断只放主图，子图里不放 `interrupt()`

**背景**：流程拆了三张子图（选题 / 写作 / 配图），很自然想把人审放进写作子图。

**选择**：所有 `interrupt()` 都留在主图。

**理由**：子图里的中断，恢复位置要靠 `checkpoint_ns` 定位，一旦子图结构变化，历史检查点就可能对不上；放主图，恢复点就是「主图的第几个节点」，语义稳定。

**代价**：子图只能表达「纯 AI 的连续动作」，人机接力全部集中在主图——可读性差一点，换来的是可预测。

---

## ADR-03 子图不直接挂成节点，而是包一层 `_run_subgraph()`

**背景**：把 `CompiledStateGraph` 直接 `add_node("topics_sub", subgraph)`，结果每次 `resume` 主图都把子图连同上游重放一遍，`operator.add` 的 trace 出现 4 次重复。

**选择**：包一层函数，只把「这次新增的」trace / node_metrics 和变化的字段回传。

**理由**：子图独立编译、可单独测的价值保留了，同时不参与父图的 checkpoint 语义。

**代价**：多一层薄封装；子图内部不能自己 `interrupt()`（与 ADR-02 一致）。

## ADR-04 三种 checkpointer 并存（内存 / SQLite / PG）

**背景**：课程只有 PostgreSQL；但 CI 里装一个 PG 很重，单元测试也不该依赖外部服务。

**选择**：`--pg` / `--db` / 什么都不给，三档递进。

**理由**：测试用内存、本机跨进程用 SQLite、企业口径用 PG；同一份代码三种验证强度。

**代价**：`session()` 要处理三种分支；PG 那两个坑（autocommit 建表、连接池）必须写清楚，否则别人一用就踩。

## ADR-05 自建 trace，不接 LangSmith

**背景**：课程用 LangSmith，配置四个环境变量就有全链路。

**选择**：自建 `runs` + `events` 两张 sqlite 表 + 页面时间线。

**理由**：LangSmith 要付费、要外网；而「每一步发生了什么」本来就在 state 里，缺的只是落盘和展示。自建还能把成本表（`node_metrics`）和业务字段放一起。

**代价**：没有自动的调用树和 token 级瀑布图；要自己维护两张表。

---

## ADR-06 前端用 Vue3 全局构建，不上 Vite

**背景**：课程前端是 Vue3 + 构建链；这台机器出网受限，`npm install` 经常挂。

**选择**：`webapp/` 里放 `vue.global.prod.js` + 一个 `app.js`，FastAPI 直接静态托管。

**理由**：打开即用、改完刷新就生效、CI 不需要 Node；演示当天少一个会坏的环节。

**代价**：没有 SFC 语法、没有类型检查、组件复用靠手写；页面规模再大就必须上构建链。

---

## ADR-07 结构化输出用 JSON Mode + 手动校验，不用 `with_structured_output`

**背景**：LangChain 的 `with_structured_output()` 一行就能约束 schema。

**选择**：自己发 `response_format={"type":"json_object"}`，拿原始响应再 `model_validate`。

**理由**：前者返回的是解析后的 Pydantic 对象，**拿不到 `usage`**，`node_metrics` 就没 token 数了（课程 P50 也踩过）；自己解析还能保留原始响应用于报错。

**代价**：要自己处理「模型不听话、JSON 包在 ```里」这类脏数据，并准备文本解析兜底。

---

## ADR-08 时间旅行靠 config 里的 `checkpoint_id`

**背景**：想做「回到第 2 版重跑」。

**选择**：`{"configurable": {"thread_id": ..., "checkpoint_ns": ..., "checkpoint_id": ...}}` + `update_state(cfg, {})` + `invoke(None, cfg)`。

**理由**：这个版本的 `update_state()` **没有** `checkpoint_id` 参数（网上不少示例还在那么写，直接 `TypeError`）。

**代价**：`checkpoint_ns` 必须一起带上，否则 `KeyError: 'checkpoint_ns'`；历史会分叉（新的分支不改旧历史）。

---

## ADR-09 退役「检索 + 事实核查」那套评测

**背景**：上一版有 30 条黄金集，引用命中率 100%、一致性 98.1%。

**选择**：流程换成自媒体运营后，把那条评测线停掉，`eval.py` 删除、黄金集保留。

**理由**：指标是绑着流程的——「引用命中率」在新流程里没有对应物；保留一份跑不起来、口径又对不上的报告，比没有更糟。

**代价**：暂时失去「有数据」这个卖点；新流程的评测（选题合格率 / 成稿通过率 / 出图成功率 / 单篇成本）还没做，这是目前最大的缺口。

---

## ADR-10 发布先做成双平台落盘，不接真实平台 API

**背景**：小红书、公众号都没有开放的个人发布 API（要企业资质/审核）。

**选择**：`publish` 节点生成两个平台的形态（短文案+图集 / 长文），`write_publish()` 落到 `outputs/publish/{platform}/`。

**理由**：链路完整可演示，又不依赖平台资质；将来接真实 API 时，只需替换 `write_publish()` 这一层。

**代价**：不是真发布，简历里必须说成「发布稿生成」，不能吹成「对接了小红书开放平台」。
